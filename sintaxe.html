Lógica, web e C# no celular, em sessões de 10 minutos que ensinam de verdade.

Sintaxe é um app de bolso para aprender a programar prevendo, consertando e escrevendo código que roda de verdade. Começa pela lógica de programação e segue por dois caminhos: web (HTML, CSS e JavaScript) e back-end com C#. O foco principal é o ponto em que mais gente trava: fazer o JavaScript funcionar dentro do HTML.

O que "ensinar de verdade" significa aqui
começar
Do básico do básico, explicado como para uma criança.
medir
Domínio por habilidade, não XP nem sequência de dias.
lembrar
Revisão espaçada (FSRS) com notificação no momento certo.
entender
Ver a execução: pilha, escopos, event loop, box model.
transferir
Projetos reais, publicados direto do app.

Canvas de telas

25 telas agrupadas pelo caminho do aluno: entrar → lógica → aprender → JS na página → praticar → arena → C# → construir. Arraste para navegar ou use os atalhos.

Entrar

Descobrir objetivo, tempo disponível e o que a pessoa já sabe. Em menos de 3 minutos ela está numa sessão feita para ela.

Lógica de programação

A base das duas trilhas. Começa no nível zero, explicada como para uma criança. Depois o algoritmo é escrito em português e aparece em JavaScript e em C#, e o aluno executa à mão antes de o computador executar.

Aprender

Ideia curta, previsão antes de executar, feedback sobre o engano específico e depois a pessoa escreve com um teclado próprio para código.

JS na página

foco principalOnde mais gente trava: ligar o JavaScript ao HTML. A receita é sempre a mesma, com uma cor para cada parte: pegar o elemento, ouvir um evento, reagir.

Praticar

Achar bugs, igualar layouts e recuperar da memória, em formatos pensados para toque em vez de digitação longa.

Arena

modo de práticaLuta por turno em que o golpe é o código. Serve para praticar e revisar o que já foi aprendido; as lições continuam calmas. Cada inimigo é um erro clássico e cada módulo termina com um chefão.

C# e .NET

Do primeiro Console.WriteLine até uma API com banco de dados. O mesmo método do resto do app: prever, ver a memória, entender o erro antes de corrigir.

Construir

Projetos com checkpoints que cabem numa sessão, um tutor que pergunta em vez de responder, e um progresso que mostra aprendizado.

Do básico do básico

Toda linguagem começa no nível zero, explicada como para uma criança de 10 anos aprender. Ninguém precisa saber nada antes. Quem já sabe pula o nível zero pelo diagnóstico, mas ele existe em todas as trilhas.

  • Ideia antes do nomePrimeiro a caixa com etiqueta. Só depois a palavra "variável".
  • Coisas do dia a diaReceita, robô, caixa, controle remoto, roupa. Nada de termo técnico para explicar outro termo técnico.
  • Uma ideia por telaFrases curtas, letra grande, no máximo duas frases antes de uma ação.
  • Desenho antes do códigoA primeira vez que o código aparece, ele tem de 1 a 3 linhas e repete algo que o aluno já fez com o dedo.
  • Errar faz parteO erro vem com explicação e uma nova tentativa, nunca com bronca ou perda de pontos.
  • Só avança quando consegue sozinhoTrês acertos sem dica em dias diferentes antes de sair do nível zero.
L0

O computador é um robô obediente

Dar ordens na ordem certa (a receita do sanduíche), guardar coisas em caixas, fazer perguntas de sim ou não, repetir uma dança 3 vezes.

idade ← 8
F0

A página é feita de caixinhas

Uma tag é uma caixa com tampa: abre, guarda o conteúdo, fecha. O navegador lê as caixas e desenha a página. Primeiro arquivo salvo e aberto.

<h1>Olá!</h1>
C0

A roupa da página

HTML é o corpo, CSS é a roupa. Toda regra responde três perguntas: em quem, o quê e como. "No título, a cor fica vermelha."

h1 { color: red; }
J0

O computador falando com você

JavaScript são ordens que o computador cumpre na hora. O console é onde ele responde. Fazer contas, guardar nomes, juntar textos.

console.log('Oi!');
W0

O controle remoto da página

O HTML é a TV, o JS é o controle remoto. O id é o nome escrito em cada botão do controle. Primeiro botão que troca um texto.

titulo.textContent = 'Oi!';
CS0

Conversando com o computador

Um programa é uma receita. Antes de cozinhar, um professor (o compilador) confere se está tudo escrito certo. WriteLine = o computador fala. ReadLine = ele escuta.

Console.WriteLine("Oi!");

Foco: JavaScript dentro do HTML

Muita gente sabe um pouco de HTML e um pouco de JS, mas não sabe ligar os dois: onde o script fica, como ele "enxerga" a página, como fazer um campo aceitar só números. Por isso isso vira uma trilha própria, JS na página, com um método único usado em todas as lições.

As três cores são as mesmas no app inteiro: no construtor de frases, no destaque do editor, nas dicas e nas mensagens dos testes. Com o tempo, o aluno passa a enxergar qualquer código de página como pegar, ouvir e reagir.

Cinco passos, um de cada vez

O primeiro módulo monta um único arquivo em cinco etapas: onde o script fica → pegar um elemento → mudar o elemento → reagir a um clique → ler o que foi digitado. Cada lição acrescenta uma coisa só.

W1–W6

Frase antes do código

"Quando clicar no #botao, faça mudar o texto." O aluno monta a frase com blocos e vê o código gerado. Depois completa lacunas. No fim, escreve sozinho.

tela 13

Página e código ligados

Tocar num elemento da página mostra a tag no HTML e a linha de JS que o pega. A pré-visualização fica sempre a um toque do código.

tela 12

Os erros clássicos viram lições

null por script no lugar errado, fn() no listener, keydown em vez de input, value tratado como número, esquecer preventDefault. Cada um tem explicação visual e um desafio de caça ao bug.

telas 14 · 16

Formulários de verdade

Validar com HTML (required, pattern), bloquear e formatar com JS (só números, máscaras), habilitar o botão quando tudo estiver válido. Os testes digitam, colam e usam o teclado do celular.

tela 15

Revisão com a mesma receita

Os cartões de revisão pedem para escrever pegar, ouvir e reagir para situações novas ("quando mudar o select, mostre o preço"), para o método virar reflexo.

tela 18

Arena: luta por turno

Um modo de prática em formato de jogo de luta por turno. Não é "acertou a pergunta, ganhou um soco": o golpe é o próprio código. Quem entende o conceito luta melhor, e quem não entende vê exatamente onde errou. As lições e o nível zero continuam calmos; a Arena serve para praticar o que já foi aprendido.

Conceito aprendidoVira no jogoExemplo de golpe
VariávelA mochila: guarda energia, poções, vidalet pocoes = 2;
if / seReagir ao inimigoif (inimigo.temEscudo) quebrarEscudo();
for / paraGolpe múltiplofor (let i = 0; i < 3; i++) socar();
while / enquantoFúria até o inimigo cair (gasta energia a cada volta)while (inimigo.vida > 0) socar();
FunçãoCombo com nome, criado por você e reutilizávelfunction combo() { chutar(); socar(); }
Evento (JS na página)Contra-ataque automáticoinimigo.addEventListener('ataque', defender);
Classe (C#)Criar o seu próprio lutadorclass Ninja : Lutador { … }
  • Por turno, sem relógioPensar com calma é parte do jogo. Nenhum turno tem tempo limite.
  • Prever é defenderNa vez do inimigo, ele mostra o código do ataque. Quem prevê o dano certo escolhe a defesa certa.
  • Inimigos são erros clássicosFantasma do null, Gêmeos do ==, Apressado ( ), Loop Infinito. Vencer um é aprender a consertar aquele erro.
  • Chefão no fim de cada móduloExige tudo o que o módulo ensinou. Os chefões de C# começam em orientação a objetos.
  • Perder não tira nadaA derrota repassa o código e mostra onde o raciocínio falhou. Dá para tentar de novo na hora.
  • Vencer depende do códigoNada de vencer chutando ou comprando poção: golpes novos só vêm de lições concluídas. Duelos contra amigos, cada um na sua vez, ficam como opção futura.

Decisões de mobile

Programar no celular é desconfortável. Então o app não tenta ser uma IDE de bolso: ele troca digitação longa por exercícios que treinam o raciocínio, e reserva a escrita de código para trechos curtos e bem apoiados.

Toque primeiro, teclado depois

Prever a saída, preencher o teste de mesa, montar frases, apontar a linha do bug, ordenar linhas e ajustar valores de CSS se fazem com o polegar. A escrita de código fica para passos curtos, com o teclado de código.

telas 07 · 08 · 13 · 16 · 17 · 18

Teclado de código próprio

Uma barra fixa com ( ) { } [ ] ; => ' `, setas de cursor, tab e sugestões do escopo atual. Fecha parênteses e aspas sozinho. No C#, as sugestões incluem tipos e ; em destaque. "ABC" alterna para o teclado do sistema.

tela 10

Sessões de 5 a 15 minutos

Cada lição cabe numa fila de ônibus. Tudo é salvo a cada passo: se a pessoa sai do app, volta exatamente onde parou.

telas 01 · 03

Notificação = revisão na hora certa

Uma notificação por dia, no horário escolhido, só quando há cartões vencendo. Ela diz quanto tempo leva ("6 cartões · 4 min") e abre direto na revisão.

telas 01 · 18

Funciona offline

Lógica, HTML, CSS e JS rodam no próprio aparelho. Compilar C#, o tutor e a publicação de projetos precisam de internet. No C#, os exercícios de previsão e o teste de mesa funcionam offline.

Arquitetura técnica

O difícil é executar código do aluno com segurança e offline, testá-lo e desenhar sua execução, tudo dentro de um app nativo. Essas peças definem a stack.

AppReact Native + Expo (TypeScript)Um código para iOS e Android. Builds e atualizações de conteúdo pelo EAS, sem esperar revisão da loja.

Roadmap

Começar pelo que mais importa: lógica e JS na página, com o teclado de código e a revisão com notificação. Visualizador e tutor entram depois de confirmar que as pessoas voltam. C# entra por último porque exige servidor de compilação.

Protótipo
